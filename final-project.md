# Final Project

Everyone follows the same final project milestones &mdash; topic selection, an Overview Presentation (Week 7),
an Update Presentation (Week 10), and a Final Presentation & Submission (Weeks 15&ndash;16). See
[Throughout the Semester]({{ site.baseurl }}/throughout-the-semester/) for how these are scheduled and weighted,
and [Important Information]({{ site.baseurl }}/important-information/) for the full rubric and submission
checklist. What differs between undergraduate and graduate students is the **deliverable** itself.

## Undergraduate Students

- **Deliverable:** a project website, built with **GitHub Pages** (preferred), or a concise written report.
- Graded on how clearly and usably the site/app presents the project's motivation, method, and results.
- A paper-style write-up is optional, not required.

## Graduate Students

- **Deliverable:** a **paper-style write-up**, written like a short conference paper &mdash; motivation, related
  work, method, experiments/results, discussion.
- A project website or demo is optional, but is not a substitute for the paper.
- Expected to demonstrate additional novelty or technical depth beyond the undergraduate scope (see
  [About]({{ site.baseurl }}/about/#learning-outcomes)).

## What's the Same for Both

- Same milestones, dates, and presentation format.
- Same GitHub repository requirements &mdash; README, `requirements.txt`/`environment.yml`, clean structure, and
  runnable code.
- A **LICENSE** in the GitHub repository is mandatory for graduate students.
- Same grading rubric for technical implementation, experimental design/evaluation, and contribution/insight &mdash;
  only the "Deliverable quality" criterion and the license requirement differ by level.

For the complete grading rubric, final submission checklist, and guidance on building a GitHub Pages site, see
the [Final Project section]({{ site.baseurl }}/important-information/#final-project) of Important Information.
